## 2. Robustness

- **R1. Non-atomic writes.** `open(path, "w")` truncates before writing. A crash or kill mid-write corrupts `state.json` or, worse, a story file. The editor autosaves every 2s, so story files are written very often. Fix: write to a temp file, then `os.replace()`. One `write_json(path, data)` helper covers all 6 write sites.
- **R2. `load_state` swallows everything.** `except (JSONDecodeError, Exception): return None` turns validation errors and corruption into "no session" with no log line. Log it, and only treat empty or missing files as None. Also remove the session_id migration that writes inside a read.
- **R3. Restarting the server wipes the session.** `lifespan` clears `state.json` because the storyteller token lives only in memory. That defeats the "always persisted to disk" rule, and in dev every `--reload` on file save kills the game. Fix: store the token (or its hash) in `state.json`, keep the session on startup, and add an explicit "end session" for cleanup.
- **R4. Closing the storyteller tab loses control.** The token is in `sessionStorage`, so a closed tab means nobody can drive or end the session; the only option is to start over. With R3 in place, `/api/state/start` (admin-only) could have a sibling "resume as storyteller" endpoint that re-issues the token.
- **R5. Editing a story during a session breaks the session.** History stores `choice_index` and the madlib step indexes `fields[...]`. Editing choices or fields mid-session causes IndexErrors (`make_choice`, `submit_madlib`, `Run.tsx:364`). Fix: **snapshot the story into the session at `/start`** (store it in `state.json`). It also stops re-reading and re-validating the story file on every request and every broadcast (currently ~10 copies of `open → json.load → Story(**…)`).
- **R6. Story validation happens at play time, not save time.** Item choices without `item_name` only fail mid-game (422). Add Pydantic validators on `Story`: unique scene IDs, item choices have names, `scene_outcome` conditions point at real scenes, opening `target_scene_id` exists, numeric conditions have `op` and `value`. The editor shows the 422 detail.
- **R7. SSE has no heartbeat.** Reverse proxies (nginx, Cloudflare, Traefik) drop idle streams after ~60–100s, so players reconnect between scenes. Send a `: ping\n\n` comment every ~20s and add the `X-Accel-Buffering: no` header. The `dead` queue cleanup in `broadcast_state` never runs, because `put` on an unbounded queue doesn't fail. Remove it or use `put_nowait` on bounded queues.
- **R8. Admin auth fails open.** No credentials means everything is allowed, and the Dockerfile defaults to empty credentials. Log a loud startup warning when credentials are empty and `AUTH_DISABLED` isn't set explicitly.
- **R9. The rate limiter guards the wrong endpoints.** It only covers `/madlib` and `/choice`, which already need the storyteller token. Behind a proxy every client shares one IP, and the store grows without bound. Remove it, or move it to the public endpoints with `X-Forwarded-For` handling.
- **R10. `/api/state/start` silently replaces an active session** and kicks out the current storyteller. Return 409 unless `force: true`, and have the UI confirm.
- **R11. `delete_story` writes `{}` to `state.json` directly**, with no broadcast and no token reset, so connected clients show stale state. Route it through the same "end session" code path as restart.

## 5. Structure and best-practice suggestions

### Backend: split `main.py` (1,437 lines)

```
app/
  main.py          # app factory, middleware, router includes
  models.py        # Pydantic models + Story validators (R6)
  engine.py        # pure functions: inject_variables, evaluate_condition,
                   #   resolve_scene, apply_choice, replay_history, next_status
  storage.py       # load/save story & state, atomic write_json (R1)
  auth.py          # verify_admin, verify_storyteller, player session check
  sse.py           # connection registry, build_payload, broadcast, heartbeat
  routes/stories.py, routes/state.py, routes/pages.py
```

- **One state-transition helper.** Every `/api/state/*` handler repeats load → status check (409) → mutate → save → broadcast → return. Wrap that:
  ```python
  async def transition(allowed: set[SessionStatus], fn) -> GameState:
      state = require_state(allowed)       # 404 / 409
      fn(state, state.story)               # pure mutation (story snapshot, R5)
      save_state(state); await broadcast_state()
      return state
  ```
  Handlers become a few lines each, and the rules in `CLAUDE.md` ("validate, mutate, write, broadcast, return") are enforced in one place.
- **Keep game rules in pure functions** in `engine.py` (take a state, return a new state, no I/O). Most tests can then target the engine without HTTP, which is where most of the logic and bugs (B2, finale logic) live.
- **Put the variable/condition data model in one place.** `Condition` should be a discriminated union (`NumericCondition | SceneOutcomeCondition`) instead of one model with every field optional. Invalid combinations then can't be constructed.
- **Make the server send player-facing data (fixes B4 and B5).** Add `resolved.visible_choices: [display_text…]` when `choices_revealed`, plus `resolved.theme`. Then `Player.tsx` never needs the story, matching the "clients are dumb consumers" rule.

### Frontend

- **Generate the TS types from the backend.** `types/index.ts` hand-mirrors the Pydantic models, and the theme list appears 4 times (backend enum, `types`, `Editor.tsx THEMES`, `useTheme themeClasses`). Use FastAPI's OpenAPI schema with `openapi-typescript`, or at least a single `THEMES` constant exported from `types`.
- **One `request()` helper in `api.ts`.** Each of the ~17 functions repeats fetch, auth headers, `res.ok`, and `err.detail` parsing. That repetition is exactly how B1 slipped through. One helper that always attaches the token removes the class of bug:
  ```ts
  async function request<T>(path: string, init: RequestInit = {}): Promise<T> {
    const res = await fetch(path, { ...init, headers: { ...getAuthHeaders(), ...init.headers } })
    if (!res.ok) throw new ApiError(res.status, (await res.json().catch(() => ({}))).detail)
    return res.json()
  }
  ```
- **A `useAsyncAction()` hook** returning `{ run, pending, error }`. It replaces the hand-rolled `isSubmitting` / `try` / `setError` blocks in Run, Library and Editor, and makes B9-style silent failures impossible.
- **Split Run.tsx by session status.** It's one 746-line component with a giant conditional. Use `<MadlibStep/>`, `<CharacterReveal/>`, `<OpeningScene/>`, `<SceneSelect/>`, `<SceneView/>`, `<Finale/>`, chosen from a `status → component` map. Player.tsx should get the same treatment, and that also fixes B3 structurally.
- **Split Editor.tsx** (1,211 lines). Move `BUILTIN_PRESETS` into `data/madlibPresets.ts`, and split the UI into `<StorySettingsPanel/>`, `<MadlibEditor/>`, `<SceneList/>`, `<SceneEditor/>`, `<ChoiceEditor/>`, `<ConditionEditor/>`. State can live in a `useReducer(storyReducer)` so edits are typed actions, which is easier to test and allows undo later.
- **Extract the shared game UI:**
  - `<FinaleRollInfo items level/>`: the d20 text is copied 3 times.
  - `outcomeLabel(choice)`: defined twice in Run with slightly different wording.
  - `<ChoiceList/>`: storyteller and player variants share the shuffled-index mapping.
  - `<ThemedScope theme>`: wraps the repeated `className={theme} style={getThemeVars(...)}`.
- **Move inline styles to CSS.** There are 71 `style={{…}}` blocks in Editor and 13 in Run. Move them into the existing utility and page classes in `base.css` and `pages/*.css`.
- **Keep one source of truth for theme colours.** `themeVars.ts` duplicates the palette that's in `themes/*.css`. Scope the theme CSS to a class (`.theme-fantasy { --accent: … }`) and apply the class wherever a themed block is needed, then delete `themeVars.ts`.
- **Make SSE opt-in per page.** Only Run (storyteller) and Player need a stream. Move `useSSE` out of `GameProvider` (fixes B6) and keep the context for theme and token only.

### Process

- Add **CI** (pytest + `tsc -b` + `eslint`) and a **pre-commit** hook running `ruff` (format and lint) and the frontend lint.

### Does it look AI-generated? Mostly yes, on the app shell
- Indigo/violet primary buttons on charcoal, which is the default "AI palette".
- Every button is a pill with equal weight. Library cards have 5 (Play/Edit/Export/Delete), with destructive Delete next to Play.
- Everything is centred (Run madlib, Run scene, Player), and the Player view uses the "hero metric" layout (big Level/Items numbers) while the story itself is absent.
- Choice cards with a thick left border accent (Player).
- Emoji as iconography: health is 💾 (cyberpunk), 💡 (fantasy), ⭐, ● (modern), 👁 (horror), 🧠 (insanity). They render differently per OS and some are off-tone (a lightbulb in fantasy, a floppy disk as "life"). Three unused SVG health icons already sit in `static/images/`.

### What's working
- **Theme fonts already have character**: Cinzel/Crimson (fantasy), Creepster/Special Elite (horror), IM Fell (insanity) are good, non-default picks.
- **Reveal flow**: storyteller reveals privately first, then pushes to players, with shuffled order. That's a strong mechanic to build drama on.
- **Motion infrastructure exists**: ~20 keyframes in `base.css` and a `prefers-reduced-motion` block. It just isn't aimed at the moments that matter.

### Priority issues

1. **[P1] The story isn't the star.**
   - **Run**: the character blurb, then stats, then scene text, then three identical indigo buttons with tiny outcome tags. There's no scene title, no progress, and no recap of the last scene and its outcome.
   - **Player**: shows stats and choices but no scene, so phones are dead air while the storyteller reads.
   - **Fix (Run)**: a "stage" layout with the scene title and progress rail at the top, the scene text as the hero in a reading serif (~65ch), and the previous scene and outcome dimmed above it. Choices as distinct cards, with outcomes in their own column and kind colours that also carry an icon (not colour alone).
   - **Fix (Player)**: show the scene title (or `display_name`), with HP as the dominant ambient state. **No progress indicator on any player-facing screen** (phones or the TV presentation mode): players shouldn't know how far into the story they are. Only the storyteller's private Run screen shows progress. The finale is the one exception, and it gets announced with a reveal (see `finale` below). To make this real rather than cosmetic, the player payload must not carry scene totals or story structure (this fits the B4 fix: send players only `resolved` content, never the story).
2. **[P1] Themes are skins, not worlds.** Every theme is the same layout with a palette, font and emoji swapped. Insanity, which should be the wildest, is a calm teal serif. Its numeral font renders "1" like "I".
   - **Fix**: each theme gets its own SVG health icon (with full/lost states), background layer (scanlines, parchment grain, starfield parallax, fog, static), and motion profile, and a signature victory/defeat sequence.
3. **[P1] Broken and conflicting chrome.**
   - Deep Space light mode keeps the black background, so the character name and items are invisible.
   - The player toolbar (`?` and mode buttons) overlaps the character card in every theme and clips "BARTHOLOMEW" in fantasy.
   - Run forces `modern` on the storyteller, so the person setting the mood never sees the mood.
4. **[P1] Spoilers on shared screens.** The madlib screen shows the raw template (`{name}, a wanderer from {homeland}…`) and "→ fills `{name}`". Choice buttons show "−1 HP / Level Up / Elder's Map".
   - **Fix**: a **Presentation mode** toggle that hides those, plus all chrome, and goes full-screen. Players' phones could also show the current madlib *question* during creation, so they're engaged instead of staring at "being created…".
5. **[P2] Library and Editor are form-dumps.**
   - **Library**: story cards could carry a theme-rendered title (in the theme's font and background), a blurb and scene count. Play is primary, Edit/Export go behind a menu, and Delete moves to the menu with confirmation.
   - **Editor**: needs a `{key}` autocomplete/insert menu for madlib fields, a live "player sees / storyteller sees" preview, inline validation (R6), and a draggable scene list that doesn't get cut off.

### Atmosphere: the "moments" system

Every phone and the storyteller screen already receive the same state stream, so **effects can fire in sync across the whole table**. All phones flashing red at the same instant is something a paper game can't do. Implementation: diff the previous and next SSE state on the client into events, and each theme maps events to effects.

| Moment (derived from state diff) | Effect idea (theme-flavoured) |
|---|---|
| `scene_changed` | Lights-down transition: scene title fades in large, then the text "types in" or inks in (cyberpunk glitch-in, fantasy ink-bleed, horror flicker) |
| `choices_revealed` | Cards dealt in one by one with a short stagger; a subtle sting on phones |
| `hp_lost` | Single red vignette flash plus screen shake on all devices; heart icon cracks or shatters; `navigator.vibrate(200)` where supported |
| `hp_critical` (1 HP) | Persistent heartbeat pulse at the screen edges, desaturated palette |
| `item_gained` | Item card flies into the inventory with a theme glint |
| `level_up` | Upward light sweep, rank sigil animates |
| `finale` | **The reveal**: players never saw progress, so this is the first moment they learn it's the end. Everything goes dark and silent for a beat, a theme title card ("The final door", "// FINAL SEQUENCE") slams in, then the d20 rolls in with a countdown hum |
| `victory` / `defeat` | Signature end sequence per theme (e.g. fantasy: golden dawn rays; horror: blood-ink wipe; insanity: the UI "breaks" and reassembles), then the run summary (items, level, path taken) |

Ambient layer per theme (all CSS/canvas, GPU-friendly, paused when the tab is hidden): cyberpunk scanlines and rain, fantasy candle-flicker vignette, deep space parallax stars, horror fog and film grain, insanity slow warping or breathing type. Optional **ambient audio and stings** per theme, off by default, storyteller-controlled.

**Per-scene backdrops.** Each theme ships a handful of *moods* (fantasy: forest, crypt, candlelit hall, storm; horror: fog, cellar, mirror; and so on). A scene gets an optional `mood` in the editor, or uses **Auto**: a mood picked by seeding on `scene_id`. Auto varies from scene to scene but every device agrees, and a scene looks the same on replay. The server resolves it into `resolved.backdrop`, so clients stay dumb consumers, and the backdrop cross-fades on `scene_changed`. Later: an optional uploaded image per scene, layered under the theme's ambient effects.

**Theme-flavoured HP vocabulary.** The engine still counts HP; each theme names and draws it: candles (fantasy), eyes (horror), integrity (cyberpunk), oxygen (deep space), **sanity** (insanity).

**Sanity corruption (Insanity theme, and optionally horror).** Scene text, titles and choices on the player screens randomly flicker for a moment into runes (ᚠᚱᛟ…) or Zalgo text (stacked combining marks), then settle back. The rate and number of corrupted words rise as HP falls. At full sanity a word slips every few seconds; at 1 HP, bursts of words several times a second, the title starts slipping, and the background swirl speeds up. Accessibility: the real text stays in `aria-label`, and the effect is off under reduced motion and Effects: Off. (Prototyped on the canvas: the Insanity artboard has a `sanity` tweak.)

**Effect polish targets** (from reviewing the canvas; the mockups loop CSS keyframes, so they read rougher than the real thing should):
- Effects fire **once per event**, never on a loop. Each has a built-in attack → hold → release, using exponential ease-out, no linear and no bounce.
- Layer the hit: a 60–80 ms impact (flash and shake), then a slower 600–900 ms settle (vignette fades, icon transitions), with the text change landing last.
- Shake is short and damped: 3–4 decaying offsets of at most 6 px. Stagger choice deal-ins by about 120 ms, with a small rotation and a shadow landing.
- Ambient loops stay subtle (opacity changes of 10% or less) and get randomised timing, so flicker and grain don't look metronomic.
- Use canvas or WebGL for grain, fog and starfields instead of repeating CSS gradients, which band and look tiled. Pause them when the tab is hidden.
- Build a small effect test page (`/dev/moments`) to fire each event per theme and tune timings side by side.

**Safety and comfort (non-negotiable):**
- Flashes stay at or below 3 per second (WCAG 2.3.1), and nothing goes full-screen white.
- Respect `prefers-reduced-motion`.
- An in-app **Effects: Full / Subtle / Off** setting on both sides.
- Use the Screen Wake Lock API so phones don't sleep mid-scene.

### Personas: red flags
- **Storyteller mid-session (power user)**:
  - No keyboard shortcuts.
  - Has to scroll past the character blurb and stats to reach the text.
  - Choice confirmation is a modal on every pick.
  - Quit is broken.
- **First-time player on a phone in a dark room**:
  - Sees "Your character is being created!" for minutes.
  - Never sees the scene name.
  - Health is a row of emoji with no explanation of what losing one means.
  - Two corner buttons cover the character card.
- **Low-vision or colour-blind player**:
  - Deep Space light mode text is invisible.
  - Choice outcomes on Run are separated by colour only.
  - Body text in several themes is set in mono or distressed display fonts (Special Elite, Space Mono) at body size, which is hard to read.

### Minor
- Theme fonts load from Google Fonts at runtime. A local game night with flaky Wi-Fi falls back to system fonts. Self-host with `@fontsource/*`.
- The "0 players" counter is wrong (B6).
- "Remind Players of Choices" and "Show Choices to Players" toggle copy is confusing; use one button with clear state.
- The ☀️ and ? buttons are emoji or characters; give them SVG icons with labels.
